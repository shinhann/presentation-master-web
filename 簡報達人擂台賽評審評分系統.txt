給 AI 開發者的系統提示詞 (System Prompt for AI Developer)
角色設定： 你是一位精通 Google Apps Script (GAS)、Google Sheets 資料庫架構以及現代化前端 (React, Tailwind CSS, SheetJS, PWA) 開發的全端工程師。
任務目標： 請依據下方的 「軟體需求規格說明書 v75.0」，開發一套「簡報達人擂台賽評審評分系統」。
核心開發原則 (Critical Instructions)：
1. 架構模式： 嚴格遵守「前後端分離」。前端為 React Single Page Application (SPA)，部署於 GitHub Pages；後端為 GAS Web App (API)。兩者透過 JSON 進行非同步通訊。
2. 資安模型 (Proxy Pattern)： Google 試算表必須保持 「私有 (Private)」 權限。前端絕不直接存取試算表，所有讀寫請求一律透過 GAS 後端的 doGet/doPost 代理執行，並驗證 API_Key 與 Referer。
3. 前端核心技術 (React & SheetJS)：
   * React + Vite: 建構高效能的單頁應用。
   * SheetJS (xlsx): 這是關鍵技術。所有「匯入」功能（如匯入隊伍名單），必須在前端使用 SheetJS 解析 Excel/CSV 檔案，轉換為標準 JSON 格式後，再發送給後端 API 寫入。嚴禁將原始 Excel 檔傳給後端處理。
4. PWA 優先 (PWA First)： 前端必須配置 vite-plugin-pwa，支援「加入主畫面」，提供全螢幕體驗。
5. 資料一致性：
   * UUID： 隊伍 ID (Team_ID) 必須由系統自動生成 (UUIDv4)。
   * 年度隔離： 所有查詢與寫入必須帶有 Competition_Year 參數。
6. Google 表單整合策略：
   * 系統不直接對接 Google 表單 API，而是採用 「CSV 中轉模式」。
   * 管理員從 Google 表單後台下載 CSV，再透過本系統後台的 SheetJS 匯入功能進行資料載入。

**視覺風格：** 暖色系 - 專業沉穩版 (Warm Professional)

### 1. 系統架構與技術堆疊 (Architecture)


* **前端展示層 (Client Side):**
* **平台:** GitHub Pages (靜態網頁託管)。
* **技術:** HTML5, CSS3 (Materialize CSS), JavaScript (Vanilla ES6+)。
* **職責:** 介面渲染、YouTube 嵌入、**智慧型 Sticky (含還原機制)**、狀態管理 (Debounce)、**微文案邏輯判斷**、API 通訊。




* **後端邏輯層 (Server Side):**
* **平台:** Google Apps Script (部署為 Web App)。
* **執行權限:** 執行身分「我 (Me)」，存取權限「任何人 (Anyone)」。
* **職責:** 請求過濾 (Referer/API Key)、商業邏輯、併發鎖定 (LockService)、配額監控、權限分流 (Admin/Judge)。




* **資料儲存層 (Database):**
* **平台:** Google 試算表 (Google Sheets)。
* **隱私模型:** **私有 (Private)**。僅擁有者可見，程式透過 GAS 服務帳號寫入，**絕不開啟共用連結**。
* **職責:** 結構化資料儲存、歷史紀錄備份 (Snapshot)。

### 2. UI/UX 設計規範 (Design Guidelines)


* **色彩系統 (Color Palette) - 溫暖且高對比:**
* **主色 (Primary):** **暖深棕色 (Warm Dark Brown, #3E2723)** - 用於頂部導航列。象徵沉穩權威。
* **行動呼籲色 (CTA):** **赤陶紅 (Terra Cotta, #D84315)** - 用於登入、強制存檔等重要操作。
* **輔助色 (Secondary):** **深琥珀色 (Dark Amber, #F57F17)** - 用於圖示、選取狀態。
* **背景色:** 暖乳白 (#FFF8E1) 網頁底色；純白 (#FFFFFF) 卡片底色。




* **狀態識別 (Status Identification) - [雙重編碼 Double Coding]:**
* *強制搭配 Material Icons 以符合無障礙標準，不只依賴顏色。*
* 🟢 **完稿 (Completed):** 顏色 `#2e7d32` + 圖示 `check_circle` (實心打勾)。
* *定義：* 四項分數 > 0 且 評語不為空。




* 🟡 **暫存 (Draft):** 顏色 `#fbc02d` + 圖示 `edit` (鉛筆) 或 `hourglass_empty`。
* *定義：* 分數已填但未滿，或分數已滿但評語為空。




* ⚪ **未評 (Empty):** 顏色 `Gray` + 圖示 `radio_button_unchecked` (空心圓)。
* 🔴 **錯誤 (Error):** 顏色 `#c62828` + 圖示 `error` (驚嘆號)。




* **版面佈局原則:**
* **桌面版:** 左右分欄 (Split Pane)。左導航 300px，右內容自適應。
* **行動版:** 單欄流式佈局 + **可展開式 Sticky Mini Bar**。

### 3. 資料庫結構規劃 (Google 試算表)


**注意：此表為「廚房」，僅系統擁有者有權限進入。**


1. **System_Config (系統設定):**
* `API_Key`: 通訊金鑰 (自訂亂碼)。
* `Admin_Password`: 管理員登入密碼 (直接在此欄位設定)。
* `Judge_Passwords`: 存放 JSON 格式的 9 組評審密碼 (如 `{"Category1_JudgeA": "1234", ...}`)。
* `Last_Snapshot_Time`: 最後快照時間。




2. **Year_Config (年度設定):**
* 年度, 規準連結, 簡章連結, 系統鎖定狀態.
* `Category_Definitions`: 定義三大類別名稱。




3. **Teams (隊伍資料):**
* 年度, 類別, 組別, 作品資料, YouTube連結, Link_Note (連結備註)...




4. **Scores (評分數據):**
* 欄位: 年度, 類別, 組別, 評審代號, 隊伍ID, 各項分數.
* **評語 (Comment):** 允許空值寫入 (支援漸進式存檔)。
* **Session_ID:** 用於偵測重複登入。




5. **Final_Results (總成績表):** 總成績、排名、獎項。
6. **[Hidden] Backup_Timestamp:** 管理員執行快照時產生的隱藏備份表。

### 5. 後端 API 功能規格 (Backend Specifications)


#### A. 安全性與限制 (Security)


1. **Referer Check:** 強制檢查 Header，拒絕非 GitHub Pages 的請求。
2. **API Key:** 所有請求必須夾帶 Key。
3. **權限分流:** `createSnapshot` 僅限 Admin Token 觸發。
4. **隱私保護:** 試算表權限保持預設 (Private)，僅透過 Service Account (Me) 存取。


#### B. 核心邏輯


1. **`submitScore`:**
* 接收評分資料 (允許空評語)。
* 使用 LockService (30s timeout) 防止寫入衝突。
* 更新 Session ID。




2. **`createSnapshot`:**
* 複製並隱藏工作表，命名為 `Backup_YYYYMMDD_HHMMSS`。




3. **`login`:**
* 驗證類別與密碼。
* 回傳該類別下所有國中/國小隊伍資料。

3. **Performance:** 前端 Debounce (3秒) 減少 API 呼叫。

4. 後端 API 功能需求 (Google Apps Script)
GAS 專案需部署為「執行身分為：我 (Me)」、「存取權限：任何人 (Anyone)」，並具備以下機制：
A. 安全與穩定性核心
      * API Key 驗證： 所有請求必須夾帶 API_Key，否則回傳 401 Unauthorized。
      * 伺服器端驗證 (Validation)： 接收分數時，後端需再次檢查數值是否在合法範圍 (例如內容 <= 40)，防止惡意竄改。
      * 併發鎖定 (LockService)： 在寫入 Scores 與 Teams 表時使用互斥鎖，防止多位評審同時送出導致資料覆蓋。
      * CORS 支援： 允許前端網域的跨來源資源共用。
B. API 端點 (Endpoints)
      * doGet() / doPost()：路由分發器。
      * login：驗證評審/管理員密碼。
      * getData：取得當年度隊伍、規準連結、系統狀態。
      * submitScore：寫入評分數據。
      * importData：匯入 CSV 或外部試算表資料。
      * getResults / saveResults：計算與儲存總成績。
      * sendMail：執行郵件寄送。
